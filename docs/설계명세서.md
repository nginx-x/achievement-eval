# 지필평가 문항분석 웹앱 — 설계명세서 (v1.1.0)

> 대상: 기존 KICE `webapp_mid`(https://kice-se.shinyapps.io/webapp_mid/) 재구현·개선
> 검증: 실제 예시데이터로 **핵심 지표 검증 완료**.

## 0. 한 장 요약

- **무엇을**: NEIS 출력 **문항정보표(1개)** + **반별 학생답 정오표(N개)** 를 올리면 문항별 정답률·변별도·신뢰도·성취수준·오답분석과 **"봐야 할 문항"을 자동으로 짚어 주는** 문항분석 도구.
- **핵심 개선 4가지**:
  1. **인사이트 자동화** — "예상난이도 vs 실측 불일치", "위험 문항", "정답오류 의심"을 자동 요약(사용자 최대 불만 해소).
  2. **벌크 업로드 + 실시간 검증** — 반별 파일을 여러 개 올리면 브라우저가 병합·오류검사·현황표시(전처리 노동 제거).
  3. **성취수준 역전 위험 플래그** — 나이브 규칙(예시 18/31 오탐) 대신 **효과크기·표본·유의성을 반영한 로버스트 규칙**.
  4. **속도·UX** — 클라이언트 즉시 계산으로 **서버 왕복 제거** + 지표별 도움말 상시 노출.
- **개인정보(핵심)**: 분석에 학생 **이름이 전혀 필요 없음** → 마스킹이 아니라 **파싱 즉시 이름·학번 폐기**(미수집·미전송). **개인데이터(학생 응답·총점 포함)는 서버로 보내지 않고 브라우저 안에서만** 처리. 이름은 필요 시 이 브라우저 메모리에만 opt-in 표시.
- **기술스택**: React+TS 클라이언트 계산 / 저장백엔드 / ECharts / 정적호스팅 + 비교표 제시.

## 1. 배경과 문제 정의

### 1.1 재현 대상(장점 수용)
KICE `webapp_mid` 계승: 기술통계·신뢰도(α)·문항 난이도(정답률)·문항 변별도·성취수준 분포(A~E)·성취수준별 정답률·(있는 경우) 오답 반응 분포.

### 1.2 개선 대상(단점)
①예상난이도 정합성이 안 보임, 인사이트를 사용자가 직접 생각해야 함 ②느림 ③성취수준 역전 위험 플래그 부재 ④신뢰도·정답률·변별도 도움말(적정범위) 부재 ⑤벌크 업로드 불가(반별 파일 수작업 병합 강요). ⑥NEIS 노이즈행(직인·소계·줄바꿈 연속행)로 파싱 까다로움 ⑦학번도 PII ⑧오답 보기(정오표 숫자) 미활용 → 매력적 오답·정답오류 분석 부재 ⑨성취기준/내용영역 롤업 부재.

## 2. 입력 데이터 명세 (실측 기반)

### 2.1 문항정보표(`*_문항정보표.xlsx`) — 1개
NEIS 리포트, 시트 1개. **병합셀 없음**(실측 mergeCell=0) — 시각적 병합은 "위장 병합"(빈 셀+테두리)이므로 언머지 로직 불필요. 실제 난점은 **줄바꿈 연속행·직인/소계 노이즈행·숫자 float('1.0')**.

- **문항 표 컬럼**: `문항번호 | 내용영역 | 성취기준 | 난이도(어려움/보통/쉬움: ○) | 배점 | 정답`. 난이도 ○ = 출제자 **예상난이도**.
- **노이즈 행(스킵)**: 페이지 바닥 직인행(끝 셀에 학교명), 소계행(`총합계`·`비율(%)`).
- **파싱 규칙(2패스, ★정정)**:
  1. **1패스**: A열이 정수(float 정수화 `Math.round`)인 행 = 문항 시작행 식별.
  2. **2패스**: 각 문항 시작행 ~ 다음 시작행 전까지의 행 중 **직인/소계 패턴을 제외한 연속행의 텍스트를 이어붙여** 내용영역·성취기준을 재구성.
  - > 이유(실측): 11번 문항은 내용영역이 R20에서 잘리고 나머지가 R22에 있으며 그 사이 R21에 직인행이 낀다. "정수 AND 성취기준 채워진 행만" 규칙은 R22를 버려 **11번 텍스트가 소실**된다. → 골든테스트에 "11번 내용영역 전체 문자열" 고정.

### 2.2 학생답 정오표(`*_정오표.xlsx`) — 반별 N개 (핵심)
NEIS 출력, **원본은 반 단위 1파일**.
- **메타행**: `2026학년도 1학기 주간 3학년 1반 기말고사 사회` → 학년/학기/반/시험/과목.
- **헤더**: `반/번호 | 학번 | 이름 | 1..N(문항) | 선택형점수 | 서답형점수 | 기타점수 | 영역총점`.
- **정답행·배점행**: 문항별 정답키·배점. 분석 정답은 XLSX/PDF 모두 **학생답정오표의 정답행만 단일 진실원으로 사용**한다. 문항정보표의 정답란은 분석·대조·경고에 사용하지 않는다.
- **응답 인코딩(선택형)**: `.`=정답, `숫자(1~5)`=단일 응답, `A~Z`=NEIS 복수응답 조합 코드, `-`=무표기. 복수정답 문항은 **정확 조합별 응답분포**와 **선택지별 포함률**을 함께 산출한다.
- **점수 재구성(선택형)**: `총점 = 만점 − Σ(틀린 문항 배점)`. > 실측 130/130 일치.
- **서답형/부분점수(✅검증)**: 정오표에는 서답형 **문항별 점수가 없고 `서답형점수` 합계만 존재**(배점행에 파트별 만점: 선택형 90/서답형 10/기타 0). → 서답형은 **단일 폴리토머스 의사문항으로 의제**해 분석(§3.0). 총점 = 선택형(재구성) + 서답형점수 + 기타점수로 정합 확인.
- **컬럼 파싱(★)**: 헤더행에서 `1..N` 문항 컬럼 범위를 **동적 확정** 후 정답/배점/학생행을 동일 인덱스로 슬라이싱(정답행은 후행 점수칸이 비어 인덱스 밀림 주의). `반/번호`는 정규식 `^\d+/\d+$`, 결번 허용.

### 2.3 벌크 업로드 & 실시간 검증
- **입력**: 문항정보표 1개 + 정오표 여러 개(드래그&드롭). **역할·반 인식은 파일명이 아니라 내부 메타행 우선**(파일명 변경·접미어 대응), 현황표에서 드롭다운으로 교정.
- **실시간 처리**: 업로드 즉시 파싱→병합→검증→현황표 갱신(서버 왕복 없음).

| 검사 | 등급 | 표시 |
|---|---|---|
| 문항 수 일치 | ⛔ | "문항 수 불일치(31 vs 30)" |
| 학생답정오표 정답키 일치(반간) | ⛔ | "학생답정오표 정답 상이(Q7)" |
| **배점 일치** | **⛔(격상)** | "배점 상이 — 이 상태로 계산 시 결과 신뢰 불가" |
| 중복 학번/반 중복 | ⚠ | 위치 표기 |
| 총점 재구성 불일치 | ⚠→유형분기 | 부분점수 문항은 유형별 검증 |
- **복구 흐름(★)**: 각 실패 항목에 **기대값 vs 실제값 + 인라인 액션(이 파일 제거/교체/무시하고 진행)**. 현황표 각 행에 개별 삭제·재업로드 버튼, **교체 시 그 파일만 재검증**.
- **부분 업로드**: 허용하되, 누락 반 상태를 §4에서 강제 각인.

### 2.4 개인정보 파이프라인
분석 지표(§3) 어디에도 이름이 쓰이지 않음 → **마스킹이 아니라 폐기**가 근본 대책.
1. **기본값: 이름·학번 컬럼 파싱 즉시 폐기.** 어떤 변수·전송 payload에도 담지 않음. 학생 식별키는 **가명코드 `S001…`(세션 내 순차 부여)**.
   - 학번을 "해시"하지 않음 — 학번은 형식이 뻔한 저엔트로피라 솔트 노출 시 사전공격으로 복원 가능. **순차코드가 더 안전**.
2. **이름 표시 opt-in**: 교사가 화면에서 학생을 봐야 할 때만, **원본 이름을 이 브라우저 메모리에만** 유지(서버 전송·저장 절대 금지). 서버 스키마에 이름 필드 **없음**.
3. **마스킹은 조인 키로 부적합(실측)**: 130명 → 마스킹 시 115 고유명, **13개 충돌그룹·28명**(김*한 3명). 표시·드릴다운은 반드시 **가명코드를 1차 키**로, 마스킹명은 보조 라벨(충돌 시 `김*한(S042)`).
4. `반/번호`도 서버엔 **반ID + 세션 내 무의미 순번**으로 치환(§5.3).

## 3. 분석 엔진 명세

> 모든 지표에 **ⓘ 도움말**(정의·식·적정범위·해석·한계). 아래 기준은 통용 휴리스틱이며 절대 기준이 아님을 함께 안내. **한국 중학교는 성취평가제(준거참조·절대평가)** 임을 전제로 규준참조 프레임을 그대로 쓰지 않음.

### 3.0 문항 유형 처리 (선택형 vs 서답형/부분점수) ★신설
- 문항유형을 UI에 구분 표기.
- **선택형(이분)**: 정답률 P=정답자/응시자, 변별도=획득점수 기준 상관(§3.3).
- **서답형/부분점수(폴리토머스)**: P 대신 **평균 획득률(획득/배점)**, 변별도·α 문항분산 모두 **획득점수(0~배점)** 기준. 총점 재구성 검증도 부분점수 반영(0/1 가정 제거). 이분 불가 시 P·점이연을 "해당 없음/획득률 대체".
- **(★2026-07 실측 확정)** NEIS 정오표는 서답형 **문항별 점수를 제공하지 않음**(`서답형점수` 합계뿐) → 서답형 전체를 **단일 의사문항 1개로 의제**: 평균 획득률·교정 변별도(서답형점수↔총점−서답형점수)·성취수준별 획득률·부분점수 분포(수준×점수). α는 선택형 문항들 + 서답형 의사문항(+기타)으로 계산해 총점과 정합(영어 예시: k=26). 문항정보표의 서답형 문항 메타(성취기준·배점·난이도)는 **참고 표시**만. 라이브 앱도 동일하게 '서답형점수' 단일 행으로 분석함(문항분석 탭 서답형 표).

### 3.1 기술통계·신뢰도
- 응시자수·평균·표준편차·최고/최저·사분위·히스토그램.
- **Cronbach α** = (k/(k−1))(1 − Σσ²ᵢ/σ²ₜ), 문항점수=**획득배점(가중)**.
- 안내: `α≥.90 매우 높음 · .80~.90 양호 · .70~.80 수용 · <.70 낮음`.
- **한계 명시(★)**: 준거참조 검사에서는 내적일관성(α)이 검사 목적에 부합하지 않을 수 있고 **점수 분산에 의존**. 배점 가중·내용 이질성으로 **tau-equivalence 위배** 시 α는 신뢰도를 과소추정 → **McDonald's ω 보조 제시**. α가 매우 높으면 **문항 중복 가능성** 안내. α를 단독 "건강" 신호로 과장 금지.
- > 실측 α=0.916.

### 3.2 문항 정답률 P (난이도) — 두 렌즈 병행 ★
- **규준참조(변별) 관점**: `P>0.90`은 "학생 간 변별 기여가 낮음". `P<0.20`은 매우 어려움/문항 점검.
- **준거참조(성취) 관점**: 높은 P는 **성취기준 도달 = 목표 달성 신호일 수 있음**. 도달률로 해석. → 높은 P를 **결함으로 자동 플래그하지 않음**(§3.9 반영).
- 시각화: 정답률 정렬 + 예상난이도 색 오버레이(§3.7).

### 3.3 변별도 D — KICE 비교정값 기본 표시 ★
- **기본 표시·정렬·필터 지표**: KICE 원본 앱과 같은 **비교정 문항-총점 상관(raw item-total)** = corr(문항 획득점수, 총점). 원본 앱과 직접 수치 비교할 수 있도록 문항표·문항지도·상세·성취기준 평균에 사용.
- **진단 보조 지표**: **교정된 문항-총점 상관(corrected item-total)** = corr(문항 획득점수, **총점 − 해당 문항 점수**). 문항 자기 상관에 의한 과대추정(part-whole 편향)을 제거하지만 기존 도구와의 정합성 우선하여 일단은 제외함.
- 배점 균일 이분문항일 때만 점이연과 일치 → 명칭은 폴리토머스에서 "문항-총점 상관"으로. α 문항분산과 **동일 획득배점 척도** 사용(지표 일관성).
- 보조: 상위27%−하위27% 정답률차(같은 편향 있으므로 교정상관을 우선).
- 안내: `≥.40 매우 양호 · .30~.39 양호 · .20~.29 개선여지 · <.20 미흡 · 음수 심각`.
- > 실측(비교정) D≥0.37. **라이브 앱 v2.1.0도 비교정 점이연을 사용**(예: 문1=0.513, 우리 계산과 일치). 교정값은 소폭 낮아지며 진단 보조값으로 병기한다.

### 3.4 성취수준 분포
- 고정분할 `A≥90·B80~89·C70~79·D60~69·E<60`(과목 커트라인 설정 가능), **원점수 100 기준**(환산 아님, §4.1).
- 분포 막대/도넛 + 반별 비교. > 실측 검증함.

### 3.5 성취수준별 정답률 + 역전 위험 플래그 ★
문항별 수준집단(A~E) 정답률로 **정상 기대(A≥B≥C≥D≥E)** 위반 탐지. 나이브 규칙은 소집단 잡음으로 **오탐 폭발**(실측 18/31).

**로버스트 규칙(표본·효과크기·유의성 반영)**:
- **1차 근거 = 교정 변별도**(§3.3)가 **통계적으로 음수**면 🔴 심각(정답오류/문항결함 강력 의심).
- **밴드 역전은 보조 신호**: 소집단(밴드 n<15)은 상위(A+B)/하위(D+E) 축약. 심각 판정은 "어떤 마진이든"이 아니라 **(a)상위−하위 정답률차의 신뢰구간(두 비율 차이 검정)이 유의하게 0 미만 + (b)최소 마진(예 ≤−.10) + (c)최소 집단 n 충족** 을 모두 만족할 때만.
- **표본부족 시 "역전 판정 보류(표본부족)"** 로 처리하고 카드에 n·경고 배너 노출. 밴드가 총점 기반이라 갖는 part-whole 순환은 상/하위 27%(교정총점) 방식과 **교차검증**.
- 심각도 3단계: 🔴심각/🟠주의(교정 변별도<.20 + 부분 역전)/🟡점검(예상난이도 불일치 등).
- > 실측: 로버스트 0/31(전부 상위>하위, D 양호). 단 이는 "건강한 데이터 1건" 결과 → **인공 양성 픽스처로 정탐도 회귀검증**(§9).

### 3.6 오답/매력도(distractor) 진단
- 문항 오답의 **보기별 선택 분포**(정오표 숫자). **하위권(D·E) 쏠림** → 오개념 진단·보충 대상.
- **매력적 오답(★재해석)**: **상위권(A·B, 최소 n 명시)** 도 특정 오답 보기에 쏠리면 → 정답과 혼동될 만큼 **잘 구성된(매력적인) 오답**으로 해석. 오답 쏠림만으로 정답오류(mis-key)를 단정하지 않음 — 정답오류 의심은 §3.5 **음의 변별도**가 담당.

### 3.7 예상난이도 vs 실측 정답률 정합성 ★ (사용자 1순위 불만)
- 출제자 예상(어려움/보통/쉬움) 대비 실측 P를 한 화면에서 대조.
- **정합성 지표(★정정)**: 예상난이도는 3범주·**대량 동점**(실측 4/17/10) → Spearman ρ 대신 **Kendall's τ-b(또는 tie-corrected)** 를 1차로, 병행하여 **등급별 평균 정답률 단조성 검정**. 계수에 **신뢰구간·n 병기**, tie 비율 높을 때 해석 주의 안내.
- **불일치 문항 자동 목록**: "쉬움 예상인데 P 낮음", "어려움 예상인데 P 높음" 등. 산점도(예상×실측 P) + 기대영역 밴드.
- > 실측: 평균 P 쉬움.85/보통.78/어려움.71(순서 맞음, 범위 크게 겹침). 자동 불일치 **Q15(예상 어려움→P.82)**. (Spearman ρ.47은 참고값, τ-b·CI로 재산출)

### 3.8 내용영역·성취기준 롤업
- 성취기준·내용영역별 평균 정답률·평균 비교정 변별도(KICE 기본)·문항수·배점합. **취약 성취기준 Top N**을 "보충 대상" 태그로 리포트 연결(§4.3 메모).

### 3.9 위험 문항 자동 요약 (인사이트 레이어) ★
대시보드 최상단 **"이번 시험에서 봐야 할 것"** 카드:
- 🔴심각(정답오류·음의 변별) / 🟠주의(변별 미흡·유의한 역전) / 🟡점검(예상난이도 불일치 등).
- **높은 P·높은 α를 단독 위험/건강 신호로 올리지 않음**(준거참조 맥락).
- 부분 데이터면 요약에 **"잠정"** 라벨. 자동 문장 예: *"31문항 중 심각0·주의0·점검1(Q15). 예상난이도 정합성 τ-b …(CI …), 신뢰도 α.92(단, 준거참조 한계·문항중복 가능성 참고)."*

## 4. UI/UX 설계

### 4.1 정보구조 / 입력 (★반영비율 정정)
```
[1 업로드 마법사] → [2 검증·가명화 미리보기] → [3 분석 대시보드] ⇄ [세션 저장/불러오기]
      요약(위험카드)·성적/분포·문항분석·성취수준(분포/수준별/역전)·오답/매력도·성취기준 롤업·문항 상세
```
- 좌측 입력(실측 반영): 라이브 앱은 업로드 후 **총점(지필)·반영비율(지필%)·4개 분할점수(기본 90/80/70/60, 수정 가능)**를 표시(총점·반영비율 둘 다 100 입력). → 우리도 동일 배치. 단 **반영비율은 수행평가 결합(M4) 시 가중에만 영향** — 지필 단독 분석에선 100 고정이므로 그 취지를 ⓘ로 명시(입력해도 지필 지표는 안 바뀐다는 혼란 방지). 성취수준은 원점수 기준 산출.
- 입력 변경 시 **즉시 재계산**(서버 왕복 없음).

### 4.2 업로드 마법사
- 큰 드롭존 + 내용 기반 역할/반 인식 + 반별 현황표(§2.3) + 진행률(파일별 스트리밍).
- **가명화/이름 미리보기**: 서버 payload에 이름 미포함을 UI로 보증. (표시 opt-in 시) 복성(남궁·황보)·외자·5글자+ 예외 규칙 적용, 개별 수동 교정 허용.

### 4.3 대시보드 / 문항 상세 / 도움말
- 문항 카드/표: 정답률 막대(예상난이도 색), KICE 방식 비교정 변별도 배지, 역전 아이콘, 오답 스파크라인.
- **모든 지표 ⓘ 툴팁**(정의·식·적정범위·해석·한계·표본경고).
- 문항 클릭 → 상세: 성취기준·배점·정답·수준별 정답률·보기별 선택 분포 + **문항별 교사 메모(세션 저장·PDF 포함)** + 플래그별 **표준 권고문** 자동 생성.
- **정렬/필터(★)**: **다중 조건 AND/OR** + 각 필터 칩에 매칭 수 배지. 요약카드의 "Q15" 링크 클릭 시 필터·정렬 자동적용 **딥링크**.

### 4.4 접근성·반응형·인쇄/내보내기 (★강화)
- **삼중 인코딩**: 위험도를 색+이모지만이 아니라 **도형/패턴(●▲■/빗금) + 텍스트 라벨(심각/주의/점검)** 으로 → **흑백 복사기**에서도 구별.
- **부분 데이터 워터마크**: 대시보드 상단·모든 탭·내보내기 산출물 머리말에 `⚠ 부분 데이터: 5개 반 중 4개(104/130명) — 결론 주의` 강제.
- **PDF 2종 분리**: ①**교과협의회용** = A4 1p 문항 요약표(문항·성취기준·P·D·예상vs실측·플래그·권고) + 위험문항 상세, ②**가정통신용** = 개별 성적(대상·내용 완전 상이).
- **PDF 파이프라인(★)**: 한글 임베드는 (a)HTML 요약 **브라우저 print-to-PDF(CSS @page, 시스템 한글폰트)** 또는 (b)서버 headless Chrome 렌더 중 택1. 차트는 PNG 삽입. jsPDF 사용 시 **서브셋 폰트**로 용량·라이선스 완화.
- **프레젠테이션/큰 글씨 모드** + 저해상도(1024px, 빔프로젝터) 레이아웃. 내보내기: 문항표 xlsx/CSV, 차트 PNG.

## 5. 세션·저장 아키텍처 (순수 클라이언트 · 서버 없음)

> 결정 반영: **서버 저장·집계 공유 기능 없음.** 모든 처리·데이터는 **브라우저 안에서만**. 서버는 정적 파일만 서빙(백엔드 0). 데이터는 본질적으로 이 브라우저에 국한 → 개인정보 거버넌스 부담이 원천적으로 최소.

### 5.1 저장 모델 (로컬 전용)
- 업로드 파일·학생 응답·총점·(opt-in)이름은 **브라우저 메모리에서만** 처리. 서버 전송 없음.
- **세션 지속(선택)**: 편의를 위해 세션을 **내 기기 IndexedDB**에 저장해 재방문 시 이어보기·수정·삭제. 학교/학년/학기/과목/시험명/분석일시로 구분. 부담되면 **"이 브라우저에서 지우기"** 한 번으로 완전 삭제.
- 다른 기기로 옮기려면 **파일 내보내기/가져오기**(로컬↔로컬). 서버 경유 없음.

### 5.2 세션 스키마 (로컬 IndexedDB)
```
LocalSession {
  localId,
  meta:{ school, grade, semester, subject, examName, examType, analyzedAt },
  config:{ totalScore, cutoffs },   // cutoffs 기본 90/80/70/60, 사용자 수정
  itemInfo:[...],
  responses:[ { pupilCode:"S001", classId:"1", answers:[...], total } ], // 이름·학번 없음(가명코드만)
  analytics:{...}, createdAt, updatedAt
}
```
- 목록 UI: 학년-학기-시험유형 필터·시험명 그룹핑·이름변경·복제·삭제·내보내기.

### 5.3 개인정보 (최소 원칙)
서버가 없고 데이터가 브라우저에만 있으므로 거버넌스는 사실상 불필요. 지키는 것은 단 두 가지:
- **이름·학번은 파싱 즉시 폐기**(가명코드 S001…). 화면 표시가 필요하면 이름은 **브라우저 메모리에만** opt-in(§2.4).
- **"이 브라우저에서 지우기"** 제공(공용 PC 대비). — 서버 전송이 없으므로 처리방침·보존기간·컴플라이언스 논의는 해당 없음.

## 6. 아키텍처·기술스택 검토 (§11 확정)

### 6.1 프론트엔드
- **React + TypeScript + Vite**(SPA, 정적배포). 파싱 **SheetJS**(`sheet_to_json({header:1, raw:false})` → float 정수화·trim·연속행 병합). 상태 Zustand+TanStack Query, 표 TanStack Table.
- 차트 **Recharts**(React 네이티브·선언형·유지보수 용이, shadcn/ui 호환; 데이터 소규모(31문항·130명)라 SVG 성능 무관). 특수 차트 필요 시에만 ECharts 폴백. **히트맵(성취수준별 정답률)은 조건부 스타일 HTML 표**로(접근성·인쇄 우수). 내보내기 PNG/PDF = `html-to-image`+`jsPDF` 또는 브라우저 print. 통계는 경량 TS(정답률·비교정 변별도·α·ω·τ-b·이항검정) — 외부 의존 최소.

### 6.2 백엔드
**없음.** 전량 클라이언트 계산 + 로컬 저장(§5)이므로 서버는 정적 파일만 서빙. DB·API·인증 불필요.

### 6.3 성능 설계 (★근거 정정)
- 속도 개선의 실제 원인은 계산량이 아니라 **서버 왕복/재렌더 제거**. Web Worker **1순위 오프로딩 대상 = xlsx 파싱(SheetJS)**(대형 디코딩이 실병목), ArrayBuffer transferable 전달 + 파일별 진행률 스트리밍. 지표 계산은 수 ms.
- NFR 벤치: 500명×50문항 파싱·재계산 목표 실측.

### 6.4 최종 추천(확정 방향)
> **React+TS(클라이언트 계산·전량 정적) + Recharts + minify + 개인 nginx 서버(정적 파일만).** 백엔드·DB·API 없음. 향후 서버측 고급 통계(IRT 등)가 필요해지면 그때 별도 검토.

### 6.5 배포(호스팅) 방법 — 개인 nginx 서버
사용자 보유 **nginx + PHP + DB** 서버에 배포(추가 비용 0, 데이터 자기 통제).
- **정적 SPA 배포**: `npm run build` → `dist/`를 nginx 웹루트에 복사. SPA 폴백 `location / { try_files $uri $uri/ /index.html; }` + 프라이버시/보안 헤더 `add_header Referrer-Policy no-referrer;`·CSP, HTTPS(Let's Encrypt). 정적 자산 self-host(외부 CDN 미사용).
- **소스 비공개·minify**: 서버엔 **빌드 산출물(minified dist)만**. 원본은 로컬/비공개 리포.
- **정적 전용**: PHP/DB 사용 안 함(전량 클라이언트). nginx는 정적 파일 서빙만.
- **PWA(권장)**: `vite-plugin-pwa`로 설치형·오프라인.
- **CI(선택)**: 커밋 시 빌드→서버 rsync/scp 자동화.
- **대안**: Cloudflare Pages/Vercel도 가능하나, 보유 서버가 있으니 그대로 활용 권장.

## 12. 유지보수성·모듈화 아키텍처
핵심 로직 재사용(모듈화)과 장기 유지보수를 최우선으로 설계.
- **계층 분리(엄격)**: `core`(순수 로직·프레임워크/DOM 의존 0) / `ui`(React 표현) / `io`(파일·저장·배포). UI·차트·호스트를 바꿔도 core는 그대로 재사용(추후 CLI·서버·수행평가 모듈에서 그대로 import).
- **core = 순수·결정적 함수**: 입력→출력만, 부작용 없음 → 단위테스트·이식 용이. 배럴 `core/index.ts`로 공개 API 고정, 내부 구현 은닉.
- **모듈 경계**: `parse`(문항정보표·정오표·병합) / `privacy`(이름·학번 폐기·가명) / `stats`(정답률·비교정 변별도·α·ω·τ-b·역전·오답·성취기준) / `insights`(위험 요약·권고문) / `analyze`(오케스트레이터: 원자료→`AnalysisResult`). 각 모듈 독립 테스트.
- **타입·상수 단일 진실원**: 도메인 타입은 `core/types.ts`, 지표 임계·커트라인·마스킹 규칙 등은 `core/config.ts` 한 곳 → 튜닝·정책변경이 한 파일로.
- **골든 테스트로 값 고정**: 예시데이터 기대값(α 0.916, A54/B24/C17/D9/E26, 변별도 문1 0.513) + 인공 픽스처(미응시·mis-key·음의 변별·부분점수)로 회귀 방지.
- **UI↔core 얇은 어댑터**: 상태스토어는 core 결과만 보관. Recharts→다른 차트, nginx→다른 호스트 교체가 core에 무영향.
- **Web Worker 격리**: 파싱/집계를 worker로 감싸되 core는 worker를 모름(순수 함수라 어디서든 실행).
- **점진 확장(OCP)**: 수행평가·서버측 IRT(필요 시) 등은 core에 모듈 추가로 확장(기존 변경 최소).
- **규약**: TS `strict`, ESLint+Prettier, 작은 함수, 주석은 "왜"에.
```
src/
  core/            # 순수 로직(재사용·이식), UI 의존 0
    index.ts  types.ts  config.ts
    parse/  privacy/  stats/  insights/  analyze.ts
    **/*.test.ts   # 골든·픽스처 테스트(vitest)
  ui/    App.tsx  components/  views/  state/
  io/    persist(IndexedDB)·export(xlsx/PDF/PNG)
  workers/  parse.worker.ts  (core 래핑)
```

## 13. UI/UX·사용성·인사이트 개선 사양 (구현 체크리스트)
> 4개 전문 렌즈(IA·교사사용성·인사이트·접근성)로 도출한 58개 항목을 주제별로 정리. 우선순위 **M1(MVP 필수)/M2/M3**. `[]`=완료기준 요지. **M1 항목이 MVP 구현 범위.**

### 13.1 정보구조·내비게이션 (탭 → 단일 스크롤 대시보드)
- **[M1]** 좌측 사이드바 + **단일 스크롤 대시보드**(요약→전체성취도→문항표→성취기준), 스크롤스파이. **답지반응 탭 폐기→문항 상세로 흡수**. `[]` 탭 전환 없이 요약→상세 도달, 현재 위치 하이라이트.
- **[M1]** **요약카드=필터 프리셋**: 카드/사유 클릭 → 문항표에 해당 필터 자동적용 + 첫 문항 상세 오픈(카드-표-상세 원플로우).
- **[M1]** 세션/뷰 상태(선택문항·필터·정렬·활성반·커트라인) IndexedDB **자동저장·복원** + "이 브라우저에서 지우기".
- **[M2]** 딥링크: 뷰 상태를 URL에 직렬화(개인정보 미포함) "현재 뷰 링크 복사".
- **[M2]** 커트라인 편집 패널: 실시간 미리보기(이전 분포 고스트)+되돌리기(undo)+"기본 아님" 배지.

### 13.2 문항 표·상세·비교
- **[M1]** 모든 수치열 **헤더 클릭 정렬**(3-state, URL 반영).
- **[M1]** **다중필터 칩(AND)**: 정답률<임계·변별도<.2·역전·예상불일치·성취기준, "31개 중 N개"+초기화.
- **[M1]** **예상↔실측 시각 연결**: 행내 연결 스파크라인(예상●·실측○) + 상단 산점도, 행↔점 linked-highlight.
- **[M1]** **'예상 vs 실측' 편차 열**(방향+크기 배지, 정렬 가능; 회색음영 대체).
- **[M1]** **문항 상세 드릴다운 스플릿 패널**(지표칩+적정범위 게이지 · 답지반응 막대 · 수준별 정답률 · 성취기준 · 메모/권고), **←/→ 키 이동**.
- **[M2]** 반별 비교(멀티선택 세그먼트, small multiples, '반별 격차' 배지), 문항×반 히트맵 유의 이탈 강조.
- **[M2]** 문항 간 비교 트레이(담기 체크→하단 카드 대조, 최대 3~4).
- **[M3]** 문항 상세 '시험 내 상대위치' 백분위(절대기준 통과+상대 하위=점검 참고).

### 13.3 인사이트·자동 내러티브 (표 → 의사결정)
- **[M1]** 요약카드 **3단 템플릿**: 진단 → 근거(효과크기·95%CI·n) → **권고 액션**(대상 성취기준코드+동사: 재검토/보충/재보정).
- **[M1]** **"한 줄 총평"**(위험 0건이어도): 평균·최난문항·반별 최대격차·신뢰도 자연어(협의회 첫 발언 소재).
- **[M1]** **준거참조 해석**: P≥.90 결함 아님 → '도달 양호' 중립라벨; 저변별 조건부 해석문; 지표 툴팁에 규준 vs 준거 1줄.
- **[M1]** **위험 플래그 근거 배지 상시**(효과크기+CI+n+규칙 충족 체크리스트); 표본부족→'보류(참고)'·CI가 0 포함→'참고' 자동 강등.
- **[M1]** 성취기준 **재지도 우선순위**(저성취율×배점비중×영향인원)+관련 문항·구체 재지도 권고.
- **[M2]** 매력적 오답 **오개념 카드**: 상위권 vs 하위권 오답선택률 대비 → 상위권 쏠림=매력적 오답(정답과 혼동), 하위권 쏠림=오개념·보충으로 분기. (정답오류 의심은 음의 변별도 플래그가 담당)
- **[M2]** **정답검토 시뮬레이션**: 대체정답 가정 시 정답률·변별도·성취분포 변화 미리보기 + 검토상태(유지/정정) 기록.
- **[M2]** 예상난이도 **캘리브레이션 리포트**(범주별 실측P 박스/도트, 분리 미흡 진단, 재보정 Top3).
- **[M2]** 신뢰도 **결론 문장**(α·ω 병기·준거참조 전제) + 커트라인 인접학생 K명 **분류 민감도 경고**.
- **[M2]** 성취수준 분포 **자동 진단**(미도달 규모·커트라인 민감도·수준 단조성 이상, '정규분포 기대 아님' 전제).
- **[M3]** 시험간 추이: **익명 집계 스냅샷 스키마 지금 정의** → 2회차부터 성취기준 추이·반복취약.

## 부록 B. 지표
- 정답률 P=정답자/응시자(이분). 폴리토머스는 평균 획득률=Σ획득/(N·배점).
- **교정 변별도 = corr(문항 획득점수, 총점 − 해당 문항 점수)**.
- Cronbach α=(k/(k−1))(1−Σσ²ᵢ/σ²ₜ), 문항분산=획득배점 기준. 보조 **McDonald's ω**.
- 정합성 = **Kendall τ-b**(tie 보정) + 등급별 평균 P 단조성, CI·n 병기.
- 역전(로버스트): 교정변별도<0(유의) 심각; 밴드 역전은 비율차 CI<0 + 마진 + 최소 n 동시충족 시.
- mis-key: 상위집단 특정 오답 선택률을 정답 선택률과 이항검정 비교.
